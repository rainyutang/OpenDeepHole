# 高风险模块攻击威胁分析

## 1. 目标

针对运行时指定的**单个高风险模块**，仅阅读该模块自身 `代码目录` 下的代码，快速了解其接口形式、输入来源、数据处理逻辑与安全控制职责，直接判断该模块可能面临的攻击威胁，并从本 skill 内置的 `references/attack_mode.json`（57 项攻击模式）中选择匹配的攻击模式输出简洁列表。

## 2. 执行边界与禁止事项

1. **禁止探索其它源码**：只允许查看当前高风险模块 `代码目录` 指定的文件或目录，**严禁探索、搜索或读取代码仓中的其它目录或外部模块源码**，不要追踪跨模块上下游调用链。
2. **禁止过度探索与问题挖掘**：检查完当前模块的主要代码情况（入口接口、关键数据结构、核心处理逻辑）后，**立即直接输出可能面临的攻击威胁**；不要逐行深挖具体漏洞、严禁构造利用条件或验证漏洞是否存在。
3. **严格限定模式库**：必须读取本 skill 随附的 `references/attack_mode.json` 作为唯一攻击模式来源，不得使用其它模式库，不得自行编造、改写攻击模式编号或名称。

## 3. 判断方法

1. 读取运行时提供的高风险模块信息（模块名称、代码目录、是否外部暴露面、判定原因）以及本 skill 的 `references/attack_mode.json`。
2. 仅在当前模块的 `代码目录` 内快速检查代码实际承担的功能（例如：内存与缓冲区操作、网络/文件协议解析、消息状态机、加解密与密钥证书处理、身份认证与权限校验、命令/路径/反序列化边界、并发与资源控制等）。
3. 对照 `references/attack_mode.json` 中的 57 项攻击模式描述，选出与该模块代码职责和输入边界相匹配的全部适用攻击模式：
   - 有足够适用模式时至少输出 10 个；确实不足 10 个时只输出全部实际适用的模式，绝不为凑数强行关联缺乏代码职能依据的模式；
   - 若确实没有任何适用模式，输出空数组 `[]`；
   - 仅判断模块“可能受到哪些攻击模式威胁”，不以确认代码中已存在具体漏洞作为前提。

## 4. 输出要求

直接将合法的 JSON 数组写入 runtime 指定的输出文件，文件内容不得包含 Markdown、代码块标记、注释或任何解释文字；聊天回复只需简短说明已完成文件写入。

输出格式保持极简，顶层为当前模块的攻击威胁 JSON 数组，数组每项仅包含以下 3 个字段：

- `pattern_id`：必须原样取自 `references/attack_mode.json` 的 `攻击模式编号`（单元素数组取该字符串，多元素按原顺序以 `、` 连接）。
- `pattern_name`：必须原样取自同一条目的 `攻击模式名称`，与 `pattern_id` 严格配对。
- `description`：用一两句简洁中文说明结合本模块代码功能，为什么该模块可能面临此攻击模式威胁（不描述具体漏洞细节或修复建议）。

同一模块列表中 `pattern_id` 不得重复。无匹配项时写入 `[]`。

### 输出示例

```json
[
  {
    "pattern_id": "ODH-PROTO-01",
    "pattern_name": "协议长度计数与帧边界失配",
    "description": "该模块负责解析外部输入的协议报文头部长度与字段计数并读取载荷，可能面临畸形长度或帧边界失配数据的攻击威胁。"
  },
  {
    "pattern_id": "ODH-PROTO-12",
    "pattern_name": "协议字段取值与跨字段约束绕过",
    "description": "该模块根据报文中的消息类型、标志位与参数组合分派处理逻辑，可能面临非法字段取值组合绕过业务约束的攻击威胁。"
  }
]
```
