# 六道门复核

每个漏洞和最终攻击链都必须独立通过以下六道门。

## 1. 流程门（Process）

步骤 0、所选验证路径、反方审查和结论所需阶段是否完整？是否读取了真实代码并保留证据？

## 2. 可达性门（Reachability）

攻击者是否能从真实入口到达危险操作？调用者约束、校验和状态机是否允许触发条件成立？

## 3. 真实影响门（Real Impact）

是否存在可证明的机密性、完整性、可用性、认证或授权影响？不要把可利用性降低等同于不存在漏洞，也不要把普通错误处理缺陷夸大成安全影响。

## 4. PoC 验证门（PoC Validation）

伪代码 PoC 是否完整？可执行/单元测试 PoC是否成功，或是否有合理且具体的跳过理由？负向 PoC 是否明确前置条件？是否存在人工绕过？

## 5. 数学边界门（Math Bounds）

涉及数值和边界时是否有完整类型、约束和逐步证明？不涉及时是否给出明确的不适用理由？

## 6. 环境门（Environment）

实际语言、版本、编译器、运行时、部署和保护配置是否支持声称的攻击？区分“完全阻止”与“仅提高门槛”。

## 判定

| 条件 | 结论 | 严重性 |
|---|---|---|
| 六道门全部通过 | TRUE POSITIVE | high |
| 任意一道门失败 | FALSE POSITIVE | low |
| 任意门未评估、阶段失败或证据缺失 | 未完成，可重试 | 不生成 |

每道门必须输出布尔值和具体证据。不得用总评替代逐门结论。
