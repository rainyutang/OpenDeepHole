# 扫描自动续扫

新建扫描默认开启“自动续扫”，所有扫描模式都可在创建时关闭。开启后，扫描主流程与去误报任务均结束时，服务端检查当前未完成或可重试失败的工作，自动执行现有续扫流程。关闭浏览器不影响续扫。

## 次数和任务范围

- 首次扫描不计入，同一扫描累计最多自动续扫 3 次。每轮包含候选点审计、威胁分析、挖掘引擎和符合条件的去误报；沿用手动续扫的成功结果、任务索引与检查点。
- 同时恢复扫描和去误报只计 1 次，仅恢复去误报也计 1 次。所有任务完成即停止；3 次用完仍有剩余工作时显示上限提示，仍可手动续扫。
- 手动续扫不占自动次数，也不会清零次数。复制扫描仅复制开关，新扫描从 0 次开始。
- 关闭“自动去误报”时，不自动首次启动复核。用户手动启动过但未完成的复核仍可自动续跑；用户明确停止的复核不会自动重开。
- 新发现的首次去误报仍可随扫描即时执行；已经失败的复核统一由自动续扫预算管理。漏洞验证不属于本功能的续扫范围。

## 等待和停止

关联 Agent 离线、更新中、没有可用模型或上一执行尚未退出时，显示等待原因，后台定期重新检查。派发前的预检查失败不消耗次数；领取轮次后准备或派发失败计作一次尝试。

扫描详情的“停止”会停止主流程及活动去误报，同时撤销待启动的自动续扫。即使上一轮已经结束、下一轮尚未启动，也可以停止。之后手动续扫会恢复自动判断，但保留已使用次数。单独停止去误报不取消其他扫描任务。

## 持久化与并发

创建 API（含外部集成）增加 `auto_resume_enabled`，默认 `true`。扫描详情、摘要及 `scan_status` SSE 增加 `auto_resume_enabled`、`auto_resume_count`、`auto_resume_state`、`auto_resume_reason`。状态为 `idle`、`pending`、`running`、`waiting`、`paused`、`exhausted`；次数上限固定为 3，不由客户端提交。

自动轮次与主扫描的 `execution_revision` 分开保存，因此仅去误报续扫同样计数。数据库预留协调手动和自动续扫；完成报告按执行身份更新，用户停止和删除优先。后台从持久化待办恢复，未派发的过期预留保留次数并更换派发令牌，阻止旧工作进程再次派发；已经派发的执行由现有 Agent 恢复机制接管。

后端启动自动补齐 SQLite/PostgreSQL 字段及调度表。历史扫描默认关闭，不自动补跑；旧请求创建的新扫描默认开启。部署需要更新后端和前端，Agent 复用既有续扫协议。
