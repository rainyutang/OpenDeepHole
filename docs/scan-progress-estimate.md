# 扫描整体进度与预计剩余时间

扫描详情首页和共享扫描首页在“当前扫描”下显示整体进度条及预计剩余时间。此处的估算独立于静态候选审计的 `progress`；任务数量、预计完成时刻和任务生成说明不在新卡片中展示。

## 计算口径

- 覆盖当前扫描已经创建的任务，以及根据本扫描问题发现率预测的后续自动去误报工作。已有漏洞验证也计入；不预测尚未创建的验证任务。预测只影响展示，不创建任务或改变调度。
- 当前模型池的计划、排队和运行任务与完整终态历史合并，按逻辑任务 ID、计划任务 ID 和最新 revision 去重；不会使用分页任务列表或任务总数历史峰值代替完整数据。
- 复用业务分类：威胁分析、候选点审计、威胁审计、威胁模式审计、去误报、漏洞验证等。威胁分析内部各阶段共用该类别的平均值。
- 每类只采纳成功、有限且大于零的执行耗时。已有 1 个同类样本即可估算；至少 3 个有效时间样本时使用“最近 20 个均值的 70%＋本扫描该类全部样本均值的 30%”。没有同类样本时使用本扫描其他任务的平均耗时先粗估；没有任何有效样本时才暂不报剩余时间。
- 数据范围严格限定为当前 `scan_id`，包括本扫描续扫保留的有效已完成任务和独立去误报、验证任务。其他扫描的结果与耗时不参与估算，即使属于同一用户或同一 Agent。
- `logical_duration_seconds` 记录同一逻辑任务各次模型 lease 的累计执行时间，包括自动重试、格式修复和原 Session 纠错，排除排队等待。旧任务使用原 `duration_seconds`；模型单次 lease 的耗时统计保持原义。

候选点审计、威胁审计和威胁模式审计分别使用业务完成数和剩余数。已结束任务（含失败、取消）计满权重；运行任务使用此前尝试耗时加当前执行耗时，最多计入该权重的 90%；待执行任务不计完成权重。业务队列尚未登记到模型池、回执暂时不齐或已结束类别缺少成功样本，都不再阻断其他任务的 ETA。

每类审计发现率为“成功审计产生的、符合复核条件的 AI 确认问题数／成功审计数”；仅关联已完成审计，排除临时问题和已取代产物，允许一次审计发现多个问题。无同类样本时使用本扫描综合发现率。各类预计新增量为剩余审计数乘发现率，再扣除这些未结束审计已经上报的问题数（最低为零），相加后向上取整；没有任何成功审计时不凭空预测发现率。关闭自动去误报时只计已创建的手动复核。

去误报以完整处理一个问题为单位，按复核执行身份和问题索引汇集各阶段耗时。已有有效完整结果后使用本扫描每问题均值；冷启动时以本扫描单阶段均值估算，对抗式暂按 3 阶段，fp-check 暂按 2 阶段，观察到深度路径后按 7 阶段（从标准路径升级为 8 阶段）修正。问题业务待办、模型阶段队列与预测量去重，已执行阶段的时间计入完成权重。

剩余时间取共享并发、各类当前执行速度、单个任务或完整复核的串行时间、模型能力容量瓶颈的最大值；存在预测问题时，在审计尾部保留最后一个问题的复核时间。有效并发优先采用本扫描实际运行数，尚未运行时采用当前启用且可用的模型容量，不重复累加共享槽位。整体进度的分母包括预计新增复核工作量；发现率或速度变化可以使进度下降、ETA 增长。这是粗略估计，不预判模型未来开放时段或其他扫描的资源竞争。

## 状态与刷新

- 主扫描和已创建的后续任务全部结束才显示 `100%` 和 `0 分钟`；执行期间最高显示 `99%`。
- 启动准备且尚无有效耗时样本，或已无已知可计时工作但流程尚未结束时，显示“估算中”。离线、阻塞、异常、取消时显示“暂无法估算”。全部实际工作结束时清除未兑现的预测量。
- 独立验证通过自身 execution owner、revision 和 Agent session 上报模型池，主扫描结束不会清除仍有效的验证任务。
- 首次打开立即获取估算，此后每 60 秒更新；原有 SSE 和 30 秒轻量状态兜底继续更新其他业务信息，但普通进度不触发估算重算。大模型池消息仅触发概览读取，保留状态和执行版本供跨 Worker 生命周期通知使用，不额外触发详情分页或绕过估算缓存。完成、取消、离线和执行切换立即更新。前端按执行版本和计算时间选择较新摘要，旧响应不能回滚估算。

## API 与兼容性

`GET /api/scan/{scan_id}` 和 `GET /api/v2/scans/{scan_id}/overview` 增加可选的 `progress_estimate`：

```json
{
  "progress": 0.68,
  "remaining_seconds": 2100,
  "state": "ready",
  "calculated_at": "2026-11-09T12:00:00+00:00",
  "execution_revision": 2,
  "active": true
}
```

`state` 为 `ready`、`estimating`、`unavailable` 或 `complete`；不能估算时 `remaining_seconds` 为 `null`。`active` 指示是否仍存在正在执行的扫描或后续工作。共享接口复用同一计算，仅查询当前扫描。估算读取或计算异常时返回 `progress_estimate: null`，概览仍返回已有业务状态；已有页面保留同一执行版本的先前估算。

估算按存储实例、扫描 ID 和执行版本缓存 60 秒，每个后端进程最多 256 条；同键并发请求合并，缓存命中不新增估算数据库查询，也不复制或遍历任务历史。缓存容量满时等待在途计算，避免无限排队；客户端断开不取消其他请求共享的计算。普通进度通知不使缓存失效，生命周期变化通过现有状态及轻量 SSE 通知处理，不额外查询数据库。

缓存未命中时仅读取本扫描任务元数据，并复用概览已有业务计数。新增问题发现率和完整复核统计固定使用 2 条扫描范围内的 SQL，不逐个问题查询；没有验证记录时跳过验证状态查询。复用现有扫描、任务和结果索引，不返回任务 Prompt、报告或 Session 正文。所有查询和估算在存储工作线程完成，不设固定一秒执行预算；只有读取或计算失败时降级。需更新后端和前端，无需 Agent 更新、数据回填或数据库迁移。

扫描数据 GET 请求在 30 秒无响应后结束本次前端等待并允许重试，不会中断后端数据库计算或 Agent 业务任务。首次加载失败提供重试入口；刷新失败保留当前内容，单独提示获取失败，恢复后通过重试、SSE 或定时刷新更新攻击树、审计状态和问题。
