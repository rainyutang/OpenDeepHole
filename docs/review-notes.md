# 问题判定依据

用户可在主页的「问题判定依据」页面保存漏洞判定时需要考虑的业务背景、输入约束等信息。每条只有标题和内容，内容支持 Markdown；条目属于当前用户。

创建扫描时开启「问题判定依据」并勾选所需条目，也可在扫描侧边栏同名页面随时启用、选择已有条目、新增并选用、编辑或取消选用。编辑个人条目会影响选用它的扫描；取消选用只解除当前扫描关联，个人库删除则移除所有关联扫描中的对应文件。

Agent 在 `~/.opendeephole/scans/<scan_id>/review-notes/` 保存当前选用的 `标题.md`。平台变更后主动同步，Agent 确认文件更新后生效；离线时先保存到平台，重连后补齐。同步失败会在页面提示。目录只保留当前内容，不保存历史版本或逐漏洞副本。关闭功能会清空该目录内的文件。中文标题保留，非法文件名会转换，重名文件会追加标识。

启用且选用条目后，现有复核提示词增加：

> 复核时请参考并关注 `{目录}` 下的问题判定依据文件，按当前问题需要查看相关内容。

模型按需查看，不要求全部读取，不增加复核步骤或报告字段。每条漏洞开始前不向后端拉取内容。已被模型读取的内容不会被自动替换，也不会自动重跑已完成的复核。

部署需同步更新后端、前端和 Agent。数据库启动时自动创建新表，已有扫描默认关闭。公开和分享页面不提供此功能。
