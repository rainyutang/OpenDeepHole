# 威胁分析覆盖图

扫描详情的「威胁分析」页在分析产物下方显示文件树矩形图。扫描尚在分析时也能进入该页，查看先上报的文件清单。

## 采集与更新

1. 新扫描在威胁分析启动后，在后台线程遍历本次 `code_scan_path`；续扫在项目和扫描路径校验完成后立即启动清单复用或补采，与配置初始化、索引和审计并行。未指定子范围时使用项目根目录。遍历不调用模型、不创建分析任务，也不改变现有模型的提示词、工具、攻击模式审计或产物结构。
2. 清单保存到 `~/.opendeephole/scans/<scan_id>/coverage/file-inventory.json`，完成遍历后立即走独立接口上报。上报队列使用独立 stream，不排在威胁分析结果后面。
3. 页面收到清单通知后显示灰色底图；收到分析产物通知后在同一棵树上更新标注，保留当前目录与选中路径。两份数据的到达顺序都受支持，分析失败时保留底图，采集失败也不改变分析状态。
4. SSE 推送资源变更通知，页面按需读取覆盖数据；重新连接、恢复标签页可见和手动刷新会补拉。数据尚未完整时每 30 秒补拉一次。

文件清单保存到独立 `scan_file_inventories` 表，不写入 `threat_analysis`，也不放进现有分析 JSON 产物。服务端只读取清单和已保存的分析产物，不访问扫描客户端的文件系统。

## 统计口径

- 全集为本次扫描根目录下采集到的普通文件，包含隐藏文件、无扩展名文件；不受静态分析语言或扩展名过滤器限制。目录保持树形结构，本次扫描工作目录位于扫描范围内时显式排除，避免把运行产物算入全集。
- 矩形面积按文件数分配；目录按后代文件数分配，空目录保留一个面积权重但不计入分母。全部目录项共同分配当前图表的面积，不再按 80 项折叠；普通目录展开后代，高风险目录模块保留为整个范围，进入目录后可查看内部文件。
- 高风险范围来自 `high_risk_modules_path.content`：文件路径只标注自身，目录路径标注所有已采集后代文件。多个模块或路径重叠时，文件只计一次。
- 攻击模式关联来自 `attack_tree_path.content`。模块 × 模式组合遵循现有 `threat_pattern_audit._build_targets` 的相关模块、节点回退及去重规则；产物缺少模块路径时沿用扫描根目录回退，并在关联详情中明确说明。
- 高风险模块表格和覆盖详情显示相对于本次扫描目录的 POSIX 路径，根目录显示为 `.`，两处共用覆盖接口的路径投影。内部产物及审计继续使用项目相对路径；历史项目相对、扫描相对及绝对路径统一映射到文件清单。
- 优先保留按原有基准解析后实际存在的路径；仅在完整清单能够唯一证明时，去除重复的完整扫描目录前缀，真实的同名嵌套目录保持不变。支持 Windows 盘符和 UNC 路径；不做通配符、文件名或路径后缀猜测。越界、缺失或有歧义的路径在「范围说明与未映射路径」中列出，不扩大覆盖范围。历史产物只读，不回写或重跑模型。
- 高风险覆盖率 = 高风险范围内去重文件数 / 全集文件数。攻击模式关联覆盖率 = 至少关联一个攻击模式的去重文件数 / 全集文件数。模式高亮只改变显示，不改变分母。
- 分析未完成、没有文件或清单不完整时，覆盖率显示 `—`。合法空分析结果在完整非空清单上显示 `0.0%`。

这里的覆盖表示分析产物描述的范围，不是逐行阅读证明或审计完成率。页面不读取审计任务完成状态。点击块可查看高风险模块、关联模式及攻击树/攻击路径来源，双击目录或点击「进入此目录」继续展开。

## 图表操作

图表根据容器的实际宽高自动适配，窗口大小、浏览器缩放和详情栏变化后会重新布局，保留选中路径与模式筛选。格子使用紧凑间距和小标签，空间不足时隐藏文字，完整路径和关联仍可通过悬停、点击或搜索查看。格子数量较多时使用画布绘制全部节点，不增加页面元素数量；方向键切换路径，Home / End 跳到首尾，Enter 进入目录。

「全屏总览」扩大到当前屏幕，退出按钮或 Esc 恢复原页面；「返回全图」返回扫描根目录；「收起详情」可进一步扩大图表，收起后点击格子仍保留选中状态，使用「显示详情」查看关联。小屏默认收起详情。极小格子可能不足一个屏幕像素，可搜索路径或进入目录查看细节。

## 边界与恢复

为避免循环或越界，遍历不跟随符号链接；符号链接、特殊文件、无法读取的目录，以及达到数量/时间限制都会作为采集问题列出。单次最多 200,000 个文件及目录条目（包含根目录），遍历预算 120 秒，超过限制的清单标记为不完整，不以已采集部分冒充全集。模型进度不等待遍历；客户端在退出本次扫描前收尾独立采集任务。

同一扫描的首份完整清单固定为统计分母，续扫优先复用本地 JSON 或服务端清单；不完整、失败、取消的清单可以在续扫时重新采集。采集上报绑定启动时的扫描执行版本及客户端会话，旧执行迟到的上报不会覆盖新执行。重复上报幂等，完成后的「采集中」通知不会让图退回等待状态。扫描删除时一并清理清单，并拒绝迟到写入。

历史扫描没有独立清单时，页面明确提示暂无清单；升级后的新扫描或续扫才会采集。不会从分析结果反推全集，也不会修改历史分析产物。

对于已经存在的任务，更新扫描客户端后使用原有「停止 → 续扫」入口即可补齐图。只要同一扫描已有可用的高风险模块与攻击树产物，清单到达后就直接显示标注，无需重新运行威胁分析，也无需等待本轮审计结束；即使本轮未恢复威胁分析阶段，也会独立补采清单。索引等待、索引失败或初始化提前退出不会丢弃已启动的采集；用户再次停止时取消采集，下次续扫可重新补采。若尚无可用分析产物，则先显示底图，继续遵循原有分析恢复规则。

## 接口与部署

| 接口 | 用途 |
| --- | --- |
| `POST /api/agent/scan/{id}/file-inventory` | 独立上传，含 `inventory`、`execution_revision`、`agent_session_id` |
| `GET /api/agent/scan/{id}/file-inventory` | 客户端续扫复用完整清单 |
| `GET /api/scan/{id}/threat-coverage` | 登录用户按现有扫描权限读取 |
| `GET /api/public/scans/{id}/threat-coverage` | 集成公开令牌读取 |
| `GET /api/shared/scans/{id}/threat-coverage` | 扫描分享令牌读取 |

覆盖接口返回 `inventory`、`analysis_ready`、`modules`、`targets` 和 `unmapped`。`modules` 和 `targets` 的 `scan_relative_paths` 用于展示，`mapped_paths` 是确认命中清单的路径，原有 `paths` 保留作为诊断来源。没有清单时，使用分析包的 `scan_scope` 或扫描元数据生成可确定的相对路径，但不生成覆盖标注。目录树与统计在前端根据清单和映射构建；SSE 只发送 `file-inventory` / `threat-analysis` 资源失效通知，不广播完整文件清单。

需同步更新后端、前端和扫描客户端并重启客户端。SQLite/PostgreSQL 启动自动建表，无需手工迁移或模型配置变更。旧客户端未采集清单时仍能正常完成现有扫描。

验证命令：`PYTHONPATH=. python3 -m pytest -q tests/test_threat_module_paths.py tests/test_threat_coverage_resume.py tests/test_threat_coverage.py`；PostgreSQL 可用 `python3 scripts/run_postgres_tests.py -q tests/test_threat_module_paths.py tests/test_threat_coverage_resume.py tests/test_threat_coverage.py tests/test_scan_resume_postgres.py`。前端在 `frontend/` 执行 `npm run test:threat-module-paths`、`npm run test:threat-coverage`、`npm run test:threat-analysis-loading` 和 `npm run build`。
